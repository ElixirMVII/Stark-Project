# AETHER

ควบคุม Windows ด้วยมือผ่านเว็บแคม พร้อม HUD โฮโลแกรมแบบโปร่งใส
("AETHER" เป็นชื่อโค้ดเนม)

> **สถานะ: v1 ครบทุก milestone (M0–M4) + backlog บางส่วน**
> ใช้มือคุมเมาส์ได้ครบ (ขยับ คลิก ดับเบิลคลิก ลาก คลิกขวา สกรอล) พร้อม HUD และเสียง มีท่าพิเศษ
> (แบมือปัด 4 ทิศ, กำมือค้างเพื่อย่อหน้าต่าง, จีบสองมือเพื่อซูม, 🤟 เพื่อ ARM/DISARM),
> system tray, calibration wizard และ build เป็น `aether.exe` ที่รันได้โดยไม่ต้องมี Python
> หลัง v1 เพิ่ม: หลายจอ, ธีมสี, เมนูวงกลมเปิดแอป (👍), หยิบ/โยนหน้าต่าง (✊ + ขยับ),
> **สอนท่ามือเอง** (ผูกท่าที่คิดเองกับปุ่มลัด — ไม่ต้องเทรนโมเดล ไม่เก็บภาพ)
> และ CI ที่รัน test + build `aether.exe` บน Windows ทุกครั้งที่ push
>
> โค้ดผ่าน unit test ทั้งหมด แต่ **ยังไม่ได้ทดสอบกับกล้องจริงบน Windows** — ทำตาม
> [checklist ทดสอบด้วยมือ](#ทดสอบด้วยมือ) ก่อนใช้งานจริง และเริ่มด้วย `--dry-run` เสมอ
> ยังไม่มีกล้องก็ลอง engine และ HUD ได้ด้วย `--source mouse` (เมาส์จำลองมือ)

## สิ่งที่ต้องมี

- Windows 10/11 และเว็บแคม
- **Python 3.12 แบบ 64-bit** (MediaPipe ยังไม่รองรับ 3.13/3.14) — เฉพาะตอนรันจาก source หรือ build เอง
  ถ้าได้โฟลเดอร์ `aether\` ที่ build แล้ว ไม่ต้องลง Python (ดู [ใช้ build สำเร็จรูป](#ใช้-build-สำเร็จรูป-aetherexe))

## ติดตั้ง (PowerShell)

```powershell
git clone <repo> ; cd Stark-Project

py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1          # ถ้าโดนบล็อก: Set-ExecutionPolicy -Scope Process RemoteSigned
python -m pip install --upgrade pip
pip install -e ".[dev]"

python tools\download_assets.py       # โหลดโมเดล + ฟอนต์ ลง assets\
```

ตรวจว่า OpenCV ไม่ชนกัน — ต้องมี `opencv-contrib-python` ตัวเดียว (mediapipe ดึงมาให้เอง):

```powershell
pip show opencv-contrib-python        # ต้องเจอ
pip show opencv-python                # ต้องขึ้น "Package(s) not found"
```

ถ้ามี `opencv-python` ติดมาด้วย: `pip uninstall opencv-python` แล้ว
`pip install --force-reinstall opencv-contrib-python`

### เสียงเอฟเฟกต์ (ไม่บังคับ — ไม่มีไฟล์เสียง แอปก็ใช้งานได้ แค่เงียบ)

ชุดเสียงของ Kenney (CC0) ต้องโหลดเองผ่านเบราว์เซอร์ เพราะเว็บไม่มีลิงก์ตรงให้สคริปต์โหลด:

1. เปิด <https://kenney.nl/assets/interface-sounds> และ <https://kenney.nl/assets/sci-fi-sounds>
   กด **Download** (ข้ามหน้าบริจาคได้)
2. วางไฟล์ zip ทั้งสองไว้ที่ `assets\_downloads\` โดยไม่ต้องแตกไฟล์
3. รัน:

```powershell
python tools\download_assets.py --check   # ต้องขึ้นว่า asset ครบ
python tools\convert_sounds.py            # เลือกเสียง → แปลงเป็น WAV ลง assets\sounds\
```

ถ้า `convert_sounds.py` บอกว่าหาเสียงไหนไม่เจอ ให้ดูชื่อไฟล์ที่มีด้วย `--list` แล้วเลือกเองด้วย
`--map ROLE=FILE` เช่น `python tools\convert_sounds.py --map click=select_003.ogg`

## ใช้งาน

```powershell
python -m aether --check              # ตรวจว่าทุกอย่างพร้อม (ไม่ใช้กล้อง)
python -m aether --calibrate          # ครั้งแรก: วัดระยะจีบและพื้นที่เอื้อมของคุณ (ดูหัวข้อ Calibration)
python -m aether --teach              # สอนท่ามือเอง (ดูหัวข้อ "ท่าที่สอนเอง")
python -m aether --dry-run            # ลองก่อน: HUD ทำงานครบ แต่ไม่ส่ง input จริง
python -m aether --source mouse --debug   # ยังไม่มีกล้อง: ใช้เมาส์จำลองมือ (ดูหัวข้อข้างล่าง)
python -m aether                      # ใช้จริง
python -m aether --debug              # ใช้จริง + หน้าต่าง debug (ภาพกล้อง)
```

(ถ้าใช้ build สำเร็จรูป แทน `python -m aether` ด้วย `aether.exe` เช่น `aether.exe --calibrate`)

| ตัวเลือก | ความหมาย |
|---|---|
| `--source camera\|mouse\|replay:PATH` | แหล่งเฟรม: กล้องจริง (ค่าเริ่มต้น), เมาส์จำลองมือ (บังคับ dry-run), หรือเล่นไฟล์ที่อัดไว้ |
| `--debug` | เปิดหน้าต่าง debug ตอนเริ่ม: ภาพกล้อง + landmark + ชื่อท่า + สถานะ + FPS |
| `--dry-run` | ไม่ส่ง input ให้ OS จริง แค่ log ว่าจะคลิก/ลาก/สกรอลตรงไหน |
| `--no-hud` | ไม่แสดง HUD และไม่เล่นเสียง |
| `--config PATH` | ใช้ไฟล์ config อื่นแทน `config.toml` |
| `--calibrate` | เปิด calibration wizard ตอนเริ่ม |
| `--teach` | เปิดหน้าต่างสอนท่ามือตอนเริ่ม |
| `--no-calibration` | ไม่ใช้ค่าที่ calibrate ไว้ (ใช้ค่าใน `config.toml` อย่างเดียว) |
| `--check` | ตรวจ config, โมเดล, ฟอนต์, เสียง แล้วออก (ใช้ตรวจหลังติดตั้ง/build) |

ปิดแอปด้วย `Ctrl+Alt+Q`, เมนู **ออก** ใน tray หรือ `Ctrl+C` ใน console

### ทดลองโดยไม่มีกล้อง (`--source mouse` / `--source replay:PATH`)

**เมาส์จำลองมือ** — ใช้ลอง gesture engine และ HUD ได้ครบโดยไม่ต้องมีกล้องหรือไฟล์โมเดล
แอปจะ **บังคับ dry-run เสมอ** (เมาส์จริงทำงานตามปกติอยู่แล้ว แอปแค่ log ว่าจะสั่งอะไร)

```powershell
python -m aether --source mouse --debug
```

กด `Ctrl+Alt+G` เพื่อ ARM แล้ว reticle จะตามเมาส์

| เมาส์ / ปุ่ม | จำลองท่า |
|---|---|
| ขยับเมาส์ | ขยับมือ (จุดคุมเคอร์เซอร์อยู่ที่ตำแหน่งเมาส์) |
| กดซ้าย (ค้าง = ลาก) | จีบโป้ง+ชี้ |
| กดขวา | จีบโป้ง+กลาง (คลิกขวา) |
| หมุนล้อ | ✌️ แล้วขยับมือขึ้น/ลง (1 notch ของล้อ = สกรอล 1 notch) — หยุดหมุนแล้วมือจะ "หาย" ราว 0.4 วินาทีก่อนกลับมาที่เมาส์ |
| `1` / `2` / `3` / `4` / `5` | ท่า None / 🖐 Open_Palm / ✊ Closed_Fist / ✌️ Victory / 🤟 ILoveYou (ค้างอยู่จนกดปุ่มอื่น) |
| ลูกศร ← → ↑ ↓ | แบมือนิ่งแล้วปัดไปทิศนั้น |

- ปุ่มตัวเลข/ลูกศรใช้ได้ทั้งแป้นอังกฤษและแป้นไทย (และ numpad) แต่ **ปุ่มยังไปถึงโปรแกรมที่โฟกัสอยู่ด้วย**
  ให้คลิกที่ desktop หรือหน้าต่าง debug ก่อนกด
- ตัวอย่าง: `3` แล้วอยู่นิ่ง 0.6 วินาที = ย่อหน้าต่าง (log), `3` แล้วขยับเมาส์ = หยิบหน้าต่าง, `5` ค้าง 1 วินาที = สลับ ARM
  กด `1` เพื่อกลับเป็นมือปกติ
- หน้าต่าง debug ไม่มีภาพกล้อง (พื้นทึบ + ป้าย `SIMULATED`) แต่แสดงโครงมือจำลอง สถานะ และ event ครบ

**เล่นไฟล์ที่อัดไว้** — `python -m aether --source replay:tests\fixtures\click_x3.jsonl --debug --dry-run`
เล่นตามจังหวะเวลาเดิม จบแล้วถือว่ามือออกจากกล้อง (ไม่บังคับ dry-run — ใส่ `--dry-run` เองถ้าไม่อยากให้เมาส์ขยับจริง)

### System tray

ไอคอน reticle ที่มุมขวาล่างของ taskbar (สีฟ้า = ARMED, สีเทา = DISARMED) คลิกขวาเพื่อเปิดเมนู:

| เมนู | ผล |
|---|---|
| Arm / Disarm | สลับการคุมด้วยมือ (เหมือน `Ctrl+Alt+G`) |
| พักกล้อง | ปล่อยกล้องให้โปรแกรมอื่นใช้ (เช่นเข้าประชุม Teams/Zoom) — มือหยุดคุมเมาส์ เลือกอีกครั้งเพื่อใช้กล้องต่อ |
| เปิดพร้อม Windows | ติ๊กแล้ว AETHER เปิดเองตอน login (เริ่มแบบ DISARMED เสมอ) — ใช้ registry ของผู้ใช้ (`HKCU\...\Run`) ไม่ต้องใช้สิทธิ์ admin ปิดได้ที่นี่หรือที่ Settings > Apps > Startup |
| หน้าต่าง Debug | เปิด/ปิดหน้าต่างภาพกล้อง (ปิดหน้าต่างแล้วแอปยังทำงานต่อ) |
| Calibrate… | เปิด calibration wizard |
| สอนท่ามือ… | สอนท่าใหม่ / ลบท่า / ลองท่าที่สอนไว้ (ดูหัวข้อ "ท่าที่สอนเอง") |
| โหลด config ใหม่ | อ่าน `config.toml` + `calibration.json` + `poses.json` ใหม่โดยไม่ต้องปิดแอป — เริ่มใหม่ในสถานะ DISARMED ถ้า config ผิดจะแจ้งเตือนและใช้ค่าเดิมต่อ |
| ออก | ปิดแอป (ปล่อยปุ่มเมาส์ที่ค้างอยู่ก่อนเสมอ) |

ถ้าเครื่องไม่มี system tray: ปิดหน้าต่าง debug = ปิดแอป

### Calibration

ระยะจีบและพื้นที่ที่เอื้อมถึงต่างกันในแต่ละคน (ขนาดมือ มุมกล้อง ระยะนั่ง) แนะนำให้ calibrate ครั้งแรก
และทุกครั้งที่ย้ายกล้องหรือเปลี่ยนท่านั่ง: เมนู tray **Calibrate…** หรือ `--calibrate`

1. **ท่าพัก** — ยกมือข้างถนัดในท่าที่ใช้ชี้ ปล่อยนิ้วตามสบาย ค้างไว้ ~2 วินาที
2. **จีบนิ้ว** — แตะปลายนิ้วโป้งกับนิ้วชี้ ค้างไว้ ~2 วินาที
3. **ระยะเอื้อม** — ขยับมือเป็นวงกว้างให้ทั่วบริเวณที่เอื้อมถึงสบายๆ ~6 วินาที

แต่ละขั้นมีเวลาเตรียมตัว 1.5 วินาที และหยุดรอเองถ้าเอามือออกจากกล้อง ถ้าวัดแล้วแยกท่าไม่ออก
wizard จะบอกให้ทำขั้นนั้นใหม่ จบแล้วบันทึก `calibration.json` (ข้าง `config.toml` / ข้าง `aether.exe`)
และโหลดค่าใหม่ทันที — ค่าในไฟล์นี้ **ทับ** `pinch.on`, `pinch.off` และ `pointer.active_region` ใน
`config.toml` ถ้าอยากกลับไปใช้ค่าใน `config.toml` ให้ลบ `calibration.json` หรือใช้ `--no-calibration`
ระหว่างเปิด wizard มือจะไม่คุมเมาส์

### หลายจอ

ค่าเริ่มต้นคุมเฉพาะจอหลัก ถ้าต่อหลายจอและอยากให้มือคุมได้ทุกจอ ตั้งใน `config.toml`:

```toml
[pointer]
screens = "all"
```

- กรอบเส้นประ (active region) ถูกยืดเต็มกรอบที่ครอบ **ทุกจอรวมกัน** — เช่นสองจอวางข้างกัน ครึ่งซ้ายของกรอบ
  คือจอซ้าย ครึ่งขวาคือจอขวา จอยิ่งกว้าง มือขยับนิดเดียวเคอร์เซอร์ไปไกล (ปรับ `active_region` ให้กว้างขึ้นได้)
- จอที่วางเหลื่อมกัน (สูงต่ำไม่เท่ากัน) ตำแหน่งที่ตกในช่องว่างระหว่างจอจะถูกดึงเข้าจอที่ใกล้ที่สุด
- HUD: แผงสถานะ/telemetry/radar และ boot อยู่บนจอหลัก ส่วน reticle เข็มทิศ วงแหวนชาร์จ และคลื่นคลิก
  ขึ้นบนจอที่เคอร์เซอร์อยู่ รองรับจอที่ตั้ง scale ต่างกัน (เช่นจอหนึ่ง 100% อีกจอ 150%)
- เปลี่ยนการตั้งค่าจอ (ต่อ/ถอดจอ, ย้ายตำแหน่ง) แล้ว tray → **โหลด config ใหม่**

### Log

log ทั้งหมดอยู่ที่ `logs\aether.log` (ข้าง `config.toml` / ข้าง `aether.exe`) หมุนไฟล์เมื่อเกิน ~1 MB
เก็บย้อนหลัง 5 ไฟล์ ถ้าโฟลเดอร์นั้นเขียนไม่ได้ (เช่นวางไว้ใน Program Files) จะใช้
`%LOCALAPPDATA%\AETHER\logs\` แทน — แนบไฟล์นี้มาด้วยเวลาแจ้งปัญหา

ทุกครั้งที่ปิดแอปจะเขียนสถิติของรอบนั้นลง `logs\session-YYYYMMDD-HHMMSS.json`: จำนวน event แต่ละชนิด,
เวลาที่อยู่ในแต่ละ state, latency เฟรม→input (p50/p95), FPS ของกล้องและ HUD, จำนวน incident ที่จดไว้

### จดปัญหาและจูนค่า

**แอปทำพลาด → กด `Ctrl+Alt+M` ทันที** แอปจะเก็บ 5 วินาทีที่ผ่านมา (ตำแหน่งข้อนิ้ว + สถานะ + event —
**ไม่มีภาพ**) ลง `incidents\YYYYMMDD-HHMMSS.jsonl` แล้วป้ายมุมขวาบนกระพริบ `INCIDENT SAVED` พร้อมเสียงสั้นๆ
(เขียนไฟล์ใน thread แยก เคอร์เซอร์ไม่สะดุด) ยังไม่ต้องบอกว่าพลาดแบบไหน — ใส่ป้ายทีหลังได้:

```powershell
python tools\label_incidents.py            # ถามทีละไฟล์: 1=false_trigger 2=missed 3=jitter 4=wrong_click 5=other
python tools\report.py                     # สรุป: latency p50/p95, FPS, ท่าที่ใช้, ปัญหาที่เจอบ่อย, ควรปรับค่าไหน
python tools\replay.py incidents\20261118-093015.jsonl          # เล่นซ้ำแบบไม่มีหน้าจอ พิมพ์ timeline
python tools\replay.py incidents\20261118-093015.jsonl --promote --expect swipe_up=0 --name no_swipe_scratching
```

- `false_trigger` = ติดเองทั้งที่ไม่ได้ตั้งใจ · `missed` = ทำแล้วไม่ติด · `jitter` = เคอร์เซอร์สั่น ·
  `wrong_click` = คลิกผิดที่ · `other`
- `replay.py` ใช้ config/จอ/ท่าที่สอนเองตอนเกิดเหตุ เล่นกี่รอบก็ได้ผลเดิม
- `--promote --expect …` ย้ายไฟล์ไปเป็น test ใน `tests\fixtures\` — `--expect` คือสิ่งที่ **ควร** เกิด
  (ชื่อที่ใช้ได้เหมือน `record_landmarks.py --list-expect`) แล้ว pytest จะตรวจทุกครั้ง
  ส่งไฟล์ incident มาให้ก็ได้ ไฟล์มีแต่ตัวเลข

**ปรับค่าสดๆ:** เปิดหน้าต่าง debug แล้วกดปุ่ม `TUNE` (หรือกด `T`) จะมีแผง slider ทางขวา:
`pinch.on/off`, `one_euro.min_cutoff/beta`, `swipe_dist_x/y`, `cooldown_ms` — ขยับแล้วมีผลทันที
(มือที่ตามอยู่ไม่หลุด) ค่าที่ขัดกัน เช่น `pinch.on` สูงกว่า `pinch.off` จะไม่ถูกใช้และแผงจะบอก
กด **Save to config** เพื่อเขียนลง `config.toml` (คอมเมนต์เดิมอยู่ครบ — ถ้ามีค่า pinch ใน `calibration.json`
จะอัปเดตในนั้นด้วย ไม่งั้นค่าที่บันทึกจะถูก calibration ทับ) หรือ **Reset** กลับค่าตอนเปิดแอป

### เปิด/ปิดการคุมเมาส์ (ARM / DISARM)

แอป **เริ่มในสถานะ DISARMED เสมอ** — เห็นมือแต่ไม่ส่ง input ใดๆ ให้ Windows

| วิธี | ผล |
|---|---|
| `Ctrl+Alt+G` | สลับ ARM ↔ DISARM (ถ้ากำลังลากอยู่ จะปล่อยปุ่มเมาส์ให้ทันที) |
| 🤟 ค้าง 1 วินาที (โป้ง+ชี้+ก้อย) | สลับ ARM ↔ DISARM ด้วยมือ — มีวงแหวนชาร์จบน HUD |
| `Ctrl+Alt+Q` | ปิดแอป |
| `Ctrl+Alt+M` | จด 5 วินาทีที่ผ่านมาว่าแอปทำพลาด (ดูหัวข้อ "จดปัญหาและจูนค่า") |

ปุ่มลัดใช้ได้ทั้งตอนเปิดแป้นไทยและแป้นอังกฤษ เปลี่ยนปุ่มได้ที่ `[hotkeys]` ใน `config.toml`

### ท่ามือ

ใช้ **มือข้างถนัด** (`tracking.dominant_hand`, ค่าเริ่มต้น `right`) ยกมือให้อยู่ในกรอบเส้นประของหน้าต่าง debug
มืออีกข้างใช้เฉพาะตอนซูมสองมือ

| ท่า | ผล |
|---|---|
| ขยับมือ (ท่าอะไรก็ได้ที่ไม่ใช่ท่าข้างล่าง) | เคอร์เซอร์ขยับตามมือ — กรอบเส้นประ = เต็มจอ |
| จีบนิ้วโป้ง+ชี้ แล้วปล่อยเร็ว (< 250ms) | คลิกซ้าย (คลิกตอน **ปล่อย** นิ้ว) |
| จีบนิ้วโป้ง+ชี้ สองครั้งติดกัน | ดับเบิลคลิก (ใช้เวลาดับเบิลคลิกที่ตั้งไว้ใน Windows) |
| จีบนิ้วโป้ง+ชี้ ค้างไว้ (> 250ms) แล้วขยับ | ลาก — ปล่อยนิ้วเพื่อวาง |
| จีบนิ้วโป้ง+กลาง | คลิกขวา |
| ✌️ แล้วขยับมือขึ้น/ลง หรือ ซ้าย/ขวา | สกรอล (เคอร์เซอร์หยุดอยู่กับที่ระหว่างสกรอล) |
| 🖐 แบมือค้าง | เข้าโหมด GESTURE: เคอร์เซอร์หยุด HUD ขึ้นเข็มทิศ 4 ทิศ |
| ↳ ปัดซ้าย / ขวา | `Ctrl+Win+←` / `Ctrl+Win+→` สลับ virtual desktop |
| ↳ ปัดขึ้น | `Win+Tab` เปิด Task View (แล้วชี้และจีบเลือกหน้าต่างได้เลย) |
| ↳ ปัดลง | `Win+D` โชว์ desktop |
| ✊ กำมือค้าง 0.6 วินาที (มือนิ่ง) | ย่อหน้าต่างที่ active (ไม่ย่อ desktop/taskbar) — มีวงแหวนชาร์จ |
| ✊ กำมือแล้วขยับ | **หยิบหน้าต่าง** ใต้เคอร์เซอร์มาลาก · แบมือ = วาง · แบมือขณะยังขยับเร็ว = **โยน** (หน้าต่างไหลต่อแต่ไม่หลุดจอ) · มีหลายจอแล้วเหวี่ยงแรงไปทางจอข้างๆ = **ย้ายหน้าต่างไปจอนั้น** (ตำแหน่งบนจอเท่าเดิม) |
| จีบสองมือพร้อมกัน แล้วกาง/หุบ | ซูมเข้า/ออก (`Ctrl`+ล้อเมาส์) เคอร์เซอร์ไปอยู่กึ่งกลางสองมือ |
| 🤟 ค้าง 1 วินาที | สลับ ARM ↔ DISARM |
| 👍 ค้าง 0.6 วินาที | เปิดเมนูวงกลมเปิดแอป (ดูหัวข้อ "เมนูเปิดแอป") |
| ท่าที่สอนเอง ค้าง 0.6 วินาที | กดปุ่มลัดที่ผูกไว้ตอนสอน (ดูหัวข้อ "ท่าที่สอนเอง") — มีวงแหวนชาร์จขึ้นชื่อท่า |

วิธีปัดให้ติด: **แบมือให้นิ่งก่อน** จนเข็มทิศบน HUD สว่าง (ราว 0.3 วินาที) แล้วสะบัดมือไปทิศที่ต้องการ
เร็วๆ ราว 1/4 ของความกว้างเฟรม — ดึงมือกลับได้เลย ไม่นับเป็นการปัดกลับ ปัดครั้งถัดไปได้หลัง ~0.8 วินาที

ท่าทั้งหมดผูกกับ action ใน `[actions]` ของ `config.toml` เปลี่ยนได้โดยไม่ต้องแก้โค้ด เช่น

```toml
[actions]
swipe_up   = "alt+tab"              # ปุ่มลัดอะไรก็ได้: "ctrl+shift+esc", "f11", "win+e" …
fist_hold  = "none"                 # "none" = ปิดท่านั้น, "minimize_foreground" = ย่อหน้าต่าง
```

เคล็ดลับ

- ก่อนจีบครั้งแรก ต้องให้แอปเห็นนิ้วโป้งกับนิ้วชี้ **ห่างกัน** ก่อนหนึ่งครั้ง (กันคลิกเองตอนมือเพิ่งเข้าเฟรม)
- ตอนนิ้วใกล้จะชิดกัน เคอร์เซอร์จะช้าลงเหลือ 20% เพื่อให้คลิกตรงจุด ถ้ารู้สึกว่าเคอร์เซอร์หนืดตลอดเวลา
  แปลว่านิ้วโป้งกับนิ้วชี้อยู่ใกล้กันเกินไปตอนพัก ให้กางนิ้วออกอีกนิด หรือลดค่า `pinch.on`
- กำมือไม่นับเป็นการจีบ
- ท่าพิเศษ (🖐 ✊ 🤟) เริ่มได้เฉพาะตอนมืออยู่ในกรอบเส้นประ (active region) — มือที่วางพักต่ำกว่ากรอบ
  จะไม่ทำให้ท่าติดเอง
- ชี้เคอร์เซอร์ด้วยมือผ่อนคลายหรือชี้นิ้ว อย่าแบมือกางเต็มที่ เพราะ 🖐 คือโหมด GESTURE (เคอร์เซอร์หยุด)
- ซูมสองมือ: จีบสองมือให้ **พร้อมกัน** (ห่างกันไม่เกิน ~0.25 วินาที) ถ้ามือหลักจีบก่อนนานกว่านั้นจะกลายเป็นการลาก
- บางมุมโมเดลอาจเรียกมือขวาว่ามือซ้ายไปชั่วครู่ (มือเอียงหรือหันข้าง) แอปจะตามมือเดิมต่อถ้ามือยังอยู่ตรงที่เดิม
  การลากจึงไม่หลุด — แต่มือที่เพิ่งยกเข้าเฟรมต้องเป็นมือข้างถนัดเท่านั้น

### เมนูเปิดแอป (👍)

1. ชูนิ้วโป้ง 👍 ค้างไว้จนวงแหวนชาร์จเต็ม (ป้าย `APPS`) → เมนูวงกลมขึ้นรอบเคอร์เซอร์ เคอร์เซอร์หยุดนิ่ง
2. ขยับมือไปทางช่องที่ต้องการ (ช่องแรกอยู่บนสุด วนตามเข็มนาฬิกา) ช่องที่เลือกจะเป็นสีเน้น
3. **จีบนิ้วโป้ง+ชี้** เพื่อเปิด — หรือ **แบมือ** เพื่อยกเลิก (ไม่เลือกอะไรภายใน 5 วินาทีเมนูปิดเอง)

ตั้งรายการได้สูงสุด 8 รายการใน `[launcher]` ของ `config.toml`:

```toml
[launcher]
items = [
  { label = "Browser", run = "https://www.google.com" },
  { label = "Files",   run = "explorer.exe" },
  { label = "Code",    run = "code", args = "--new-window" },
  { label = "Docs",    run = "C:\\Users\\me\\Documents" },
]
```

`run` เป็นอะไรก็ได้ที่พิมพ์ในกล่อง Run ของ Windows (`Win+R`) ได้: ชื่อโปรแกรม, path ของไฟล์/โฟลเดอร์ หรือ URL
ปิดเมนูนี้ได้ด้วย `enabled = false` · ตอน `--dry-run` จะแค่ log ว่าจะเปิดอะไร

### ท่าที่สอนเอง

สอนท่ามือที่คิดเองแล้วผูกกับปุ่มลัด เช่น ชี้+ก้อย 🤘 = `ctrl+c` — เมนู tray **สอนท่ามือ…** หรือ `--teach`

1. ตั้ง **ชื่อท่า** (a-z, 0-9, `_`, `-`) และเลือก/พิมพ์ **ปุ่มลัด** (แบบเดียวกับ `[actions]` เช่น `ctrl+v`,
   `alt+tab`, `win+shift+s`, `minimize_foreground`) แล้วกด **เริ่มสอน**
2. **มือปกติ** (~3 วินาที) — ใช้มือแบบที่ชี้ตามปกติ ขยับไปมา จีบเบาๆ สักสองสามครั้ง
   (แอปใช้ข้อมูลนี้แยกท่าใหม่ออกจากการใช้งานปกติ)
3. **ท่าใหม่** (~3 วินาที) — ทำท่าค้างไว้ แล้วเอียง/ขยับมือเล็กน้อย ให้จำได้หลายมุม
4. ผ่านแล้วกด **บันทึก** → แอปโหลดใหม่ (DISARMED) ค้างท่านั้น 0.6 วินาทีขณะ ARMED เพื่อกดปุ่มลัด

ท่าที่ใช้ไม่ได้ (wizard จะบอกเหตุผลแล้วให้ทำขั้นนั้นใหม่):

- ท่าที่แอปใช้อยู่แล้ว: ✌️ 🖐 ✊ 🤟 และ 👍 (ถ้าเปิดเมนูเปิดแอปอยู่)
- ท่าที่นิ้วโป้งแตะนิ้วชี้หรือนิ้วกลาง (จะชนกับการคลิก) เช่น 👌
- ท่าที่คล้ายมือตอนชี้ปกติ หรือคล้ายท่าที่สอนไว้แล้ว

ข้อควรรู้

- มือต้องหัน **ทิศเดียวกับตอนสอน** (±60°) — ท่าเดียวกันที่หันคนละทิศจึงสอนเป็นคนละท่าได้ (เช่น 👍 กับ 👎
  เมื่อปิดเมนูเปิดแอป) สอนด้วยมือข้างถนัด ถ้าเปลี่ยนข้างถนัดภายหลังก็ใช้ท่าเดิมได้
- ถ้าโมเดลมั่นใจว่าเป็นท่าที่แอปใช้อยู่แล้ว (✌️ 🖐 ✊ 🤟 👍) ท่านั้นชนะเสมอ
- ระหว่างเปิดหน้าต่างนี้มือไม่คุมเมาส์ ทำท่าให้กล้องเห็นเพื่อ **ลองท่า** ได้เลย (บอกว่าตรงท่าไหนและห่างเกณฑ์แค่ไหน)
  หน้าต่าง debug ก็แสดง `pose <ชื่อ> ระยะ/เกณฑ์` ของท่าที่ใกล้ที่สุดทุกเฟรมเช่นกัน
- สอนชื่อเดิมซ้ำ = แทนที่ท่าเดิม (ใช้เปลี่ยนปุ่มลัดด้วย) · สอนได้สูงสุด 12 ท่า · ปิดทั้งหมดด้วย `poses.enabled = false`
- เก็บใน `poses.json` ข้าง `config.toml` / `aether.exe` — **มีแค่ตัวเลข landmark** ไม่มีภาพ ลบไฟล์ = ลบทุกท่า

### Target Lock + Magnetic Snap (Windows)

ขณะ ARMED แอปถามตำแหน่งของปุ่มที่อยู่ใต้เคอร์เซอร์จาก Windows (UI Automation) แล้ว

- **HUD ล็อกเป้า:** มุมกรอบ 4 มุมเด้งออกจาก reticle ไปล้อมปุ่ม พร้อมป้าย `BUTTON · Save` · จีบใกล้เต็มแล้วกรอบบีบเข้า
  และกระพริบตอนคลิก · เลื่อนไปปุ่มอื่น กรอบเด้งตามไป
- **ดูดเคอร์เซอร์:** เข้าใกล้กลางปุ่ม (ในรัศมี ~1/3 ของขนาดปุ่ม อย่างน้อย 24 px) เคอร์เซอร์จะถูกดึงเข้าหากลาง
  ทำให้กดปุ่มเล็กๆ เช่น X บน title bar ได้ง่ายขึ้น · **สะบัดมือเร็วๆ เพื่อหลุด** · ระหว่างจีบรอคลิก กรอบยึดปุ่มเดิมไว้จนคลิกเสร็จ
- ไม่ดูดตอนลาก สกรอล โหมดปัด และซูม · ปุ่มที่ใหญ่เกิน `targeting.max_size` (เช่นพื้นที่ข้อความ) ไม่ดูด
- หยุดหาเป้าเองเมื่อหน้าต่างที่ใช้อยู่เป็นแบบเต็มจอ (เช่นเกม), เป็นโปรแกรมใน `targeting.app_blocklist`,
  โปรแกรมค้าง (Not responding) หรือ Windows ไม่ให้อ่าน (หน้าต่างที่รันแบบ Administrator) — แอปค้างไม่ทำให้ AETHER ค้างตาม
- ชื่อปุ่ม (อาจเป็นหัวข้ออีเมล/ชื่อไฟล์) แสดงบน HUD เท่านั้น **ไม่ถูกเขียนลง log, incident หรือสถิติ**
  (หน้าต่าง debug แสดงแค่ชนิดกับขนาด เช่น `lock Button 46x32`)
- ปิดทั้งหมด (กลับไปทำงานเหมือนเดิม): `targeting.enabled = false` · แสดงกรอบอย่างเดียวไม่ดูด: `snap_strength = 0`

### ระบบความปลอดภัย

- เริ่มแอปในสถานะ DISARMED เสมอ และระหว่าง DISARMED ไม่มี input ใดถูกส่งให้ Windows
- มือหลุดเฟรมเกิน 300ms ระหว่างลาก → ปล่อยปุ่มเมาส์ทันที
- กล้องค้าง/หลุดระหว่างลาก → ปล่อยปุ่มเมาส์ทันที (มี watchdog แยกจาก thread ของกล้อง)
- กด DISARM, ปิดแอป หรือโปรแกรมพัง → ปล่อยปุ่มเมาส์ก่อนเสมอ
- ARMED แต่ไม่เห็นมือนาน 10 นาที (ลืมปิดแล้วลุกไป) → DISARM เอง ป้ายขวาบนขึ้น `AUTO DISARM`
  (`safety.auto_disarm_minutes`, 0 = ปิด)
- เปิดกล้องไม่ได้เพราะโปรแกรมอื่นใช้อยู่ → HUD ขึ้น `CAMERA IN USE` และหน้าต่าง debug บอกชื่อโปรแกรม
  (อ่านจากหน้า Privacy ของ Windows) แอปลองเปิดใหม่เรื่อยๆ ปิดโปรแกรมนั้นแล้วกลับมาใช้กล้องเอง
- ภาพมืดนานเกิน 3 วินาที → HUD เตือน `LOW LIGHT` (เปิดไฟ/หันหน้าเข้าหาแสง) — หน้าต่าง debug แสดง `light …`
  (`camera.low_light`, 0 = ปิด)
- ถ้าเกิดอะไรผิดปกติ: กด `Ctrl+Alt+G` หรือขยับเมาส์จริง (เมาส์จริงใช้ได้ตลอด)

### HUD

overlay โปร่งใสเต็มจอหลัก อยู่บนสุดเสมอ **คลิกทะลุได้ทั้งหมด** ไม่แย่ง focus และไม่โผล่ใน taskbar

| ชิ้น | ตำแหน่ง | แสดงอะไร |
|---|---|---|
| Reticle | ตามเคอร์เซอร์ | วงในเติมเต็มตามระยะนิ้ว (เต็มวง = จีบแล้ว เปลี่ยนเป็นสีอำพัน) · วงแหวนสีอำพันรอบนอก = เวลาที่ค้างก่อนจะกลายเป็นการลาก · **แปลงร่างตามโหมด** (ดูข้างล่าง) · คลิกแล้วหดแล้วเด้ง มีคลื่น + อนุภาคกระจาย · ลากแล้วมีเส้น trail · มือใกล้กล้อง = ใหญ่ขึ้น |
| เข็มทิศ 4 ทิศ | รอบ reticle (โหมด GESTURE) | ป้ายบอกว่าปัดทิศไหนทำอะไร · จาง = ยังไม่พร้อม (แบมือให้นิ่งก่อน) · สว่าง = ปัดได้ · ทิศที่ปัดติดจะวาบเป็นสีอำพัน |
| วงแหวนชาร์จ | รอบ reticle | เติมจนเต็มระหว่างค้าง ✊ หรือ 🤟 พร้อมป้ายบอกผล (`MINIMIZE`, `ARM`, `DISARM`) |
| ป้ายสถานะ | ขวาบน | `ARMED` / `DISARMED`, โหมดปัจจุบัน, จำนวนมือ, `DRY-RUN`, ข้อความเตือน (`CAMERA LOST`) |
| Telemetry | ซ้ายล่าง | CPU %, RAM %, FPS กล้อง, latency (เฟรม→input), เวลา |
| Hand radar | ขวาล่าง | โครงมือ 21 จุดของมือข้างถนัด (ซูมให้เต็มกรอบ) |
| Boot | กลางจอ | วงแหวนขยายเหลื่อมเวลา + ข้อความ "ถอดรหัส" เป็น `SYSTEM ONLINE` + แผง telemetry สไลด์เข้า (~1.5 วินาที) |
| กรอบล็อกเป้า | รอบปุ่มใต้เคอร์เซอร์ | ดูหัวข้อ "Target Lock + Magnetic Snap" |
| Effect | ทั้งจอ | ปัด → แสงพุ่งผ่านจอตามทิศ · ย่อหน้าต่าง → กรอบหน้าต่างยุบลงไปทาง taskbar |

- ตอน `DISARMED` ทั้ง HUD เป็นสีเทา และ reticle แสดงตำแหน่งที่เคอร์เซอร์ *จะ* ไปอยู่ (ยังไม่ขยับเมาส์จริง)
- ไม่เห็นมือข้างถนัด → reticle จางหายไป
- ปรับได้ใน `[hud]`: `opacity`, ธีมสี (`theme`), ปิดแผง (`show_telemetry`, `show_radar`),
  ปิดเสียง (`sounds`), ความดัง (`volume`), หรือปิดทั้งหมด (`enabled = false`)
- `hud.reduce_motion = true` ปิดอนุภาค การ "หายใจ" ของ reticle และแอนิเมชันตอนบูต (เหลือแค่ fade)
- `hud.quality = "low"` ไม่วาด glow ชั้นนอก และอนุภาคเหลือครึ่งเดียว — ใช้เมื่อ HUD กิน CPU มาก
  (หน้าต่าง debug แสดง `HUD draw … ms` งบคือไม่เกิน 4 ms ต่อครั้ง เกินแล้วขึ้น ⚠)

reticle แต่ละโหมดเป็นชุดค่าของวงแหวน 3 ชั้น เปลี่ยนโหมดแล้ววงแหวนค่อยๆ แปลงร่างไปหาโหมดใหม่ (ไม่เกิน 0.25 วินาที):

| โหมด | หน้าตา |
|---|---|
| ชี้ (POINTER) | วงแหวน 3 ชั้น ส่วนโค้ง 4 ช่องหมุนช้าๆ |
| ลาก | วงแหวนบีบแน่น สีอำพัน หมุนเร็ว + เส้น trail |
| สกรอล | ยืดเป็นรางแนวตั้ง ลูกศรบน/ล่างสว่างตามทิศที่สกรอลล่าสุด |
| ซูมสองมือ | ยืดเป็นรางแนวนอน |
| โหมดปัด (🖐) | กางออกเป็น 4 ทิศ |
| ค้างท่า (✊ 🤟 👍 ท่าที่สอนเอง) | วงนอกขยายกลายเป็นวงชาร์จสีอำพัน |
| DISARMED | วงเส้นประสีเทา หมุนช้ามาก |

ธีมสี (`hud.theme`):

| ธีม | สีหลัก / สีเน้น |
|---|---|
| `aether` | ฟ้า / อำพัน (เหมือนค่าเริ่มต้น) |
| `ember` | ส้ม / เหลือง |
| `verdant` | เขียว / ฟ้า |
| `violet` | ม่วง / ชมพู |
| `ice` | ขาวอมฟ้า / ฟ้า |
| `custom` (ค่าเริ่มต้น) | ตั้งเองด้วย `hud.primary` และ `hud.accent` (`"#RRGGBB"`) |

เปลี่ยนแล้ว tray → **โหลด config ใหม่** ได้เลย ธีมมีผลกับ HUD, หน้าต่าง debug, calibration และไอคอน tray

เสียง: boot, คลิก, ปล่อย (จบการลาก), ปัด, ย่อหน้าต่าง, arm, disarm, error (กล้องหลุด) — ต้องมีไฟล์ใน `assets\sounds\`
คลิก/ปล่อย/ปัด/ย่อ มีเสียง 2–3 แบบสลับแบบสุ่ม (`click_2.wav`, `click_3.wav` … ที่ `convert_sounds.py` สร้างให้)
(ดูหัวข้อ [เสียงเอฟเฟกต์](#เสียงเอฟเฟกต์-ไม่บังคับ--ไม่มีไฟล์เสียง-แอปก็ใช้งานได้-แค่เงียบ))

### อ่านหน้าต่าง debug

- เส้นโครงมือสี **ฟ้า** = มือข้างถนัด (`tracking.dominant_hand`), สี **เหลืองอำพัน** = มืออีกข้าง
- วงกลมกากบาทบนมือข้างถนัด = จุดที่ใช้คุมเคอร์เซอร์ (กึ่งกลางโคนนิ้วชี้กับนิ้วกลาง)
- ป้ายเหนือมือ: ข้างของมือ + ท่าที่โมเดลเห็น + ความมั่นใจ เช่น `RIGHT · Victory 91%`
- กรอบเส้นประ = active region (พื้นที่ในเฟรมที่ map เต็มจอ)
- ป้ายมุมขวาบน: `ARMED · <สถานะ>` หรือ `DISARMED · <ปุ่มลัด>`
- แถบมุมซ้ายล่าง
  - บรรทัด 1: `FPS` (เป็นสีเหลืองถ้าต่ำกว่า 25), `latency` = เวลาตั้งแต่ได้เฟรมจนส่ง input เสร็จ, จำนวนมือ
  - บรรทัด 2: ความละเอียดกล้อง, mirror, มือข้างถนัด, `DRY-RUN`
  - บรรทัด 3: สถานะ engine, ท่า, `pinch` = ระยะโป้ง↔ชี้เทียบขนาดมือ, ตำแหน่งเคอร์เซอร์
- แถบ `PINCH` มุมขวาล่าง: เต็ม = จีบแล้ว และมี % ของการค้างก่อนจะกลายเป็นการลาก

## ปรับค่า

แก้ `config.toml` แล้วเปิดแอปใหม่ ใส่เฉพาะ key ที่อยากเปลี่ยนก็ได้ (ที่เหลือใช้ค่าเริ่มต้น)
key ที่พิมพ์ผิดหรือค่าที่อยู่นอกช่วงจะถูกแจ้งตอนเปิดแอป ค่าที่มีผลแล้ว:

| key | ความหมาย | ปรับเมื่อ |
|---|---|---|
| `camera.index` | กล้องตัวที่เท่าไร (0 = ตัวแรก) | มีกล้องหลายตัว |
| `camera.width` / `height` / `fps` | ความละเอียดและ FPS ที่ขอจากกล้อง | |
| `camera.mirror` | flip ภาพแนวนอนเหมือนส่องกระจก | |
| `camera.low_light` | ความสว่างของภาพ (0–255) ที่ต่ำกว่านี้นานๆ แล้วเตือน `LOW LIGHT` (0 = ปิด) | เตือนบ่อยทั้งที่ใช้ได้ → ลด |
| `safety.auto_disarm_minutes` | ไม่เห็นมือนานเท่านี้ขณะ ARMED → DISARM เอง (0 = ปิด) | |
| `camera.battery_fps` | ตอนถอดสายชาร์จ (โน้ตบุ๊ก) ประมวลผลไม่เกินเท่านี้ fps เพื่อประหยัดไฟ (0 = ไม่ลด) | เคอร์เซอร์หน่วงตอนใช้แบต → เพิ่ม |
| `tracking.dominant_hand` | มือข้างถนัด `"left"` / `"right"` | ถนัดซ้าย |
| `tracking.num_hands` | จำนวนมือสูงสุดที่จับ (1–2) | |
| `tracking.min_gesture_score` / `vote_window` | ความมั่นใจขั้นต่ำของท่า และจำนวนเฟรมที่ใช้โหวต | ✌️ ติดยาก/ติดเอง |
| `pointer.active_region` | พื้นที่ในเฟรมที่ map เต็มจอ `[x0, y0, x1, y1]` | เอื้อมไม่ถึงขอบจอ → ทำให้เล็กลง |
| `pointer.one_euro.min_cutoff` | ยิ่งต่ำยิ่งนิ่ง (แต่หน่วงขึ้นตอนขยับช้า) | เคอร์เซอร์สั่น → ลด |
| `pointer.one_euro.beta` | ยิ่งสูงยิ่งตามมือทันตอนขยับเร็ว | เคอร์เซอร์หน่วง → เพิ่ม |
| `pointer.screens` | `"primary"` = จอหลักจอเดียว, `"all"` = ทุกจอรวมกัน (ดูหัวข้อ "หลายจอ") | มีหลายจอ |
| `pointer.pinch_lock_gain` | ความเร็วเคอร์เซอร์ตอนนิ้วใกล้จีบ (0 = หยุดนิ่ง) | เคอร์เซอร์ขยับตอนคลิก → ลด |
| `pinch.on` / `pinch.off` | ระยะนิ้วที่ถือว่า "จีบ" / "ปล่อย" (เทียบขนาดมือ) | คลิกไม่ติด → เพิ่ม `on`, คลิกเอง → ลด `on` |
| `pinch.drag_hold_ms` | จีบค้างนานเท่านี้จึงเป็นการลาก | ลากเองตอนตั้งใจคลิก → เพิ่ม |
| `scroll.speed` / `deadzone` / `invert` | ความเร็วสกรอล, ระยะที่มือขยับได้โดยยังไม่สกรอล, กลับทิศ | |
| `gestures.swipe_dist_x` / `swipe_dist_y` | ต้องปัดไกลแค่ไหน (สัดส่วนของกว้าง/สูงเฟรม) | ปัดไม่ติด → ลด, ปัดติดเอง → เพิ่ม |
| `gestures.swipe_window_ms` | ต้องปัดให้ถึงระยะภายในเวลาเท่านี้ | ปัดไม่ติดเพราะช้า → เพิ่ม |
| `gestures.cooldown_ms` | เวลาพักหลังท่าครั้งเดียวแต่ละครั้ง | ท่าติดซ้ำ → เพิ่ม |
| `gestures.fist_hold_ms` / `arm_hold_ms` | ต้องค้าง ✊ / 🤟 นานเท่าไร | ติดเอง → เพิ่ม |
| `gestures.zoom_step` | ระยะสองมือต้องเปลี่ยนกี่ % ต่อการซูม 1 ขั้น (0.06 = 6%) | ซูมเร็ว/ช้าไป |
| `gestures.window_grab` | ✊ แล้วขยับ = หยิบหน้าต่างลาก/โยน (`false` = ปิด, ✊ ใช้ย่อหน้าต่างอย่างเดียว) | หน้าต่างขยับเองตอนตั้งใจย่อ |
| `actions.*` | ท่าแต่ละท่าทำอะไร: ปุ่มลัด, `"minimize_foreground"` หรือ `"none"` | |
| `launcher.enabled` / `hold_ms` / `timeout_ms` / `items` | เมนูเปิดแอป: เปิด/ปิด, เวลาค้าง 👍, เวลาปิดเอง, รายการ (สูงสุด 8) | |
| `poses.enabled` / `hold_ms` | ท่าที่สอนเอง: เปิด/ปิด, ต้องค้างนานเท่าไร | ติดเอง → เพิ่ม `hold_ms` |
| `poses.sensitivity` | ความง่ายในการรับท่าที่สอนเอง (0.25–4, ค่าเริ่มต้น 1) | ทำท่าแล้วไม่ติด → เพิ่ม, ติดเอง → ลด |
| `targeting.enabled` / `snap_strength` / `escape_speed` | Target Lock: เปิด/ปิด, แรงดูด 0–1, ความเร็วที่หลุด (ความกว้างจอ/วินาที) | ดูดแรงไป → ลด `snap_strength` · หลุดยาก → ลด `escape_speed` |
| `targeting.rate_hz` / `max_size` / `show_label` / `app_blocklist` | ความถี่ที่ถาม, ขนาดปุ่มสูงสุด (logical px), ป้ายชื่อปุ่ม, โปรแกรมที่ไม่ต้องหาเป้า | browser กิน CPU → ลด `rate_hz` |
| `hotkeys.toggle_arm` / `quit` / `mark_incident` | ปุ่มลัด เช่น `"<ctrl>+<alt>+g"`, `"<ctrl>+<shift>+<f9>"` | ชนกับโปรแกรมอื่น |
| `hud.enabled` / `opacity` | เปิด HUD, ความโปร่งรวม | |
| `hud.theme` / `primary` / `accent` | ธีมสี หรือ `"custom"` + สีหลัก/สีเน้นที่ตั้งเอง (`"#RRGGBB"`) | |
| `hud.show_telemetry` / `show_radar` | เปิด/ปิดแผง telemetry และ radar มือ | บังจอ / อยากลด CPU |
| `hud.sounds` / `volume` | เปิดเสียง และความดัง 0–1 | |
| `hud.reduce_motion` | ปิดอนุภาค การหายใจ และแอนิเมชันตอนบูต | เวียนหัว / อยากให้นิ่ง |
| `hud.quality` | `"high"` / `"low"` (ไม่มี glow ชั้นนอก อนุภาคครึ่งเดียว) | `HUD draw` เกิน 4 ms |

## Build เป็น `aether.exe`

```powershell
pip install -e ".[dev,build]"
python tools\download_assets.py          # ต้องมีโมเดลและฟอนต์ก่อน (เสียงไม่บังคับ)
python tools\build_exe.py                # → dist\aether\aether.exe
dist\aether\aether.exe --check          # ตรวจ build (ขึ้นกล่องข้อความผลการตรวจ)
```

- ได้โฟลเดอร์ `dist\aether\` (~600 MB): `aether.exe`, `config.toml`, `README.md`, `LICENSES.md`
  และ `_internal\` (ไลบรารี + โมเดล + ฟอนต์ + เสียง) — คัดลอกทั้งโฟลเดอร์ไปเครื่องอื่นได้เลย
- build ใหม่ทับโฟลเดอร์เดิมได้ `config.toml` ที่แก้ไว้ข้าง exe จะไม่ถูกทับ
- exe ไม่มีหน้าต่าง console (ดู log ที่ `logs\aether.log`) ถ้าต้องการ console ไว้ debug:
  `python tools\build_exe.py --console`
- build เองด้วย PyInstaller ตรงๆ ก็ได้: `pyinstaller packaging\aether.spec --noconfirm --clean`

### ดาวน์โหลด build จาก GitHub Actions (ไม่ต้อง build เอง)

ทุกครั้งที่ push, GitHub Actions จะรัน test บน Windows และ build `aether.exe` ให้:
หน้า repo บน GitHub → **Actions** → เลือก run ล่าสุดของ workflow **CI** ที่ผ่าน (✓) →
หัวข้อ **Artifacts** → ดาวน์โหลด `aether-windows` (เก็บไว้ 14 วัน) แล้วแตก zip จะได้โฟลเดอร์ `aether\`
build นี้ไม่มีไฟล์เสียง (ชุดเสียงต้องโหลดเองผ่านเบราว์เซอร์) — ถ้าอยากได้เสียงให้ build เอง

### ใช้ build สำเร็จรูป (`aether.exe`)

1. คัดลอกโฟลเดอร์ `aether\` ไปไว้ที่ไหนก็ได้ที่เขียนไฟล์ได้ (เช่น `Documents\aether\`)
2. ดับเบิลคลิก `aether.exe` — HUD ขึ้นพร้อม `SYSTEM ONLINE` และมีไอคอนใน tray
3. ครั้งแรก: tray → **Calibrate…** แล้วกด `Ctrl+Alt+G` เพื่อเริ่มคุมด้วยมือ
4. แก้ค่าได้ที่ `config.toml` ข้าง exe แล้ว tray → **โหลด config ใหม่**

Windows SmartScreen อาจเตือนเพราะ exe ไม่ได้ลงลายเซ็น — กด *More info → Run anyway*

| คลิก/ลากใช้ไม่ได้กับบางหน้าต่าง | หน้าต่างนั้นรันแบบ Administrator (ดู "ข้อจำกัดที่รู้อยู่แล้ว") |
| ปัดไม่ติด | แบมือให้นิ่งจนเข็มทิศสว่างก่อน แล้วปัดให้เร็วและไกลขึ้น หรือลด `gestures.swipe_dist_x`/`y`, เพิ่ม `swipe_window_ms` |
| เคอร์เซอร์หยุดเองบ่อย | มือกางเต็มที่จนถูกมองเป็น 🖐 — ผ่อนนิ้วลง หรือเพิ่ม `tracking.min_gesture_score` |
| ✊ / 🤟 ไม่ติด | ต้องอยู่ในกรอบเส้นประ และค้างจนวงแหวนชาร์จเต็ม — ดูป้ายท่าในหน้าต่าง debug ว่าโมเดลเห็นเป็นท่าอะไร |
| ท่าพิเศษติดเอง | เพิ่ม `gestures.fist_hold_ms` / `arm_hold_ms` / `swipe_dist_*` หรือปิดท่านั้นด้วย `actions.<ท่า> = "none"` |
| ท่าที่สอนเองไม่ติด | เปิดหน้าต่างสอนแล้วลองท่า ดูเหตุผล: "ไม่ตรงท่าไหน" → หันมือให้ใกล้ตอนสอน สอนใหม่ หรือเพิ่ม `poses.sensitivity` · "มือปกติ" → ท่าคล้ายมือตอนชี้เกินไป เลือกท่าที่ต่างกว่านี้ · "ก้ำกึ่งหลายท่า" → ลบท่าที่คล้ายกัน |
| ท่าที่สอนเองติดเอง | เพิ่ม `poses.hold_ms` หรือลด `poses.sensitivity` · สอนท่านั้นใหม่ (ขั้น "มือปกติ" ให้ขยับ/จีบเยอะๆ) |
| ไฟล์ท่ามือเสีย | ลบ `poses.json` แล้วสอนใหม่ (แอปยังทำงานได้ แค่ไม่มีท่าที่สอนเอง) |
| ไม่มีกรอบล็อกเป้า | ใช้ได้เฉพาะ Windows และตอน ARMED · รัน `--check` ดูบรรทัด Target Lock · หน้าต่างเต็มจอ/admin/ค้าง จะไม่ล็อก |
| เคอร์เซอร์ถูกดูดจนเลื่อนออกยาก | สะบัดมือให้เร็วขึ้น หรือลด `targeting.snap_strength` / `escape_speed` |
| ปัดซ้าย/ขวาแล้วไม่มีอะไรเกิด | ต้องมี virtual desktop มากกว่า 1 อัน (กด `Win+Ctrl+D` เพื่อสร้าง) |
| ไม่เห็นไอคอนใน tray | Windows ซ่อนไว้ในลูกศร `^` ข้างนาฬิกา — ลากออกมาวางบน taskbar ได้ |
| ดับเบิลคลิก `aether.exe` แล้วไม่มีอะไรขึ้น | ดู `logs\aether.log` ข้าง exe และรัน `aether.exe --check` |
| `aether.exe` บอกว่าไม่พบโมเดล | ตอน build ยังไม่ได้รัน `tools\download_assets.py` — โหลดแล้ว build ใหม่ |
| Calibrate แล้วขึ้น "แยกท่าพักกับท่าจีบไม่ออก" | ตอนพักให้นิ้วโป้งกับนิ้วชี้ห่างกันชัดเจน ตอนจีบให้ปลายนิ้วแตะกัน และหันฝ่ามือเข้าหากล้อง |
| หลัง calibrate คลิกติดยาก/ติดเองกว่าเดิม | ลบ `calibration.json` (กลับไปใช้ค่าเดิม) แล้ว calibrate ใหม่ หรือแก้ค่าใน `config.toml` แล้วใช้ `--no-calibration` |
| ไม่มีเสียง | ยังไม่ได้รัน `tools\convert_sounds.py` (console จะบอกว่าขาดไฟล์ไหน) หรือ `hud.sounds = false` |
| HUD บังสิ่งที่อยากดู | ลด `hud.opacity` หรือปิด `hud.show_telemetry` / `hud.show_radar` |
| reticle ไม่ตรงกับเคอร์เซอร์ | แจ้งค่า scale ของจอ (Settings > Display) และความละเอียดจอ |

| จับมือไม่ติด / หลุดบ่อย | ให้มีแสงส่องหน้า นั่งห่างกล้อง 50–80 ซม. พื้นหลังไม่รก |
| ตัวหนังสือไทยใน console เพี้ยน | ใช้ Windows Terminal แทน console รุ่นเก่า |

## ข้อจำกัดที่รู้อยู่แล้ว

- คุมหน้าต่างที่รันแบบ **Administrator** ไม่ได้ (เช่น Task Manager) เพราะ Windows UIPI บล็อก input
  จากโปรแกรมที่สิทธิ์ต่ำกว่า — แอปนี้จะไม่ขอสิทธิ์ admin
- ส่ง `Ctrl+Alt+Del` ไม่ได้
- สกรอลเป็นขั้นเท่าล้อเมาส์จริง (ทีละ notch) ไม่ใช่แบบลื่นต่อเนื่อง เพื่อให้ใช้ได้กับทุกโปรแกรม
- ต้องมีแสงพอ ควรมีแสงส่องหน้า นั่งห่างกล้อง 50–80 ซม. พื้นหลังที่รกอาจทำให้จับมือพลาด
- ค่าเริ่มต้นคุมเฉพาะจอหลัก — หลายจอต้องตั้ง `pointer.screens = "all"` (ยังไม่ได้ทดสอบกับหลายจอจริง)
- HUD อยู่ใต้ UI บางอย่างของ Windows ที่อยู่ชั้นบนกว่าหน้าต่างทั่วไป (Start menu, Task View,
  หน้าจอ UAC) ตอนนั้นจะไม่เห็น reticle แต่เคอร์เซอร์จริงยังขยับตามมือ

## Privacy

- ประมวลผลในเครื่องทั้งหมด ตอนรันแอปไม่มีการต่อ network
  (มีแค่ `tools\download_assets.py` ที่ต่อ network ตอนติดตั้ง)
- ไม่บันทึกภาพจากกล้องลงดิสก์ — `calibration.json` เก็บแค่ตัวเลข threshold และพื้นที่, `poses.json` เก็บแค่
  ชื่อท่า ปุ่มลัด และรูปทรงมือเป็นตัวเลข, log และ `session-*.json` เก็บแค่สถานะ event และสถิติ (ไม่มีภาพ
  หรือพิกัด landmark), `incidents\*.jsonl` และ `tools\record_landmarks.py` เก็บแค่ตัวเลข landmark
